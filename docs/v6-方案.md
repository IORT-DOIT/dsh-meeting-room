## §1 根因取证（Lead 一手）

### ① 用户正文进与会者会话的通道
- `index.js:2119` 白名单 `['archive','notice','full']`；`:2120` `if (!mode) mode = body.pushAll === true ? 'full' : room.room.push === 'off' ? 'archive' : room.room.push;` ⇒ 房间 push 为 `full` 时，用户每条消息都以 `full` 投递。
- `index.js:646-674 deliver()`：`:651` `const full = text !== undefined && mode === 'full'`；`:652-656` 生成 `【会议室 X】<label>：<用户原文>` ⇒ 正文进入每个与会者会话（图一的核心问题）。
- 实时数据：主会议室 `push:"full"`、另一房间 `push:"notice"`（`/dsh-room/rooms` 实测）。
- `index.js:29 const PUSH_MODES = new Set(['off','notice','full'])`；`:422 if (!PUSH_MODES.has(this.room.push)) this.room.push = 'off';`（载入归一化钩子）；`:2000-2003` `PATCH /rooms {push}` 白名单校验。

### ② 与会者每轮「本轮运行失败」（图二下三条）
- 根因：`index.js:1650 const llm = this.host.ctx?.llm;` —— 插件 ctx 是 Cordis 受限代理，`inject = ['tools','webServer','agents']`，**不含 llm**，直接属性访问抛 `cannot get property "llm" without inject`。该函数由 `agent/request` 钩子 `:1701` 调用 ⇒ 抛在与会者自己那一轮 ⇒ 会话 UI 显示「本轮运行失败 cannot get property "llm" without inject」。
- 第二处：官方契约 `llm.resolveModelInfo` 是 **async**（`api-catalog.js:1370`/`:5547`），`index.js:1652-1654` 同步取值 ⇒ 只会拿到 Promise ⇒ `:1658` 拿不到 `efforts` ⇒ 返回 null ⇒ `:1703` 只发一次 warn，思考程度静默失效。**必须同时改 async/await**，否则修好访问也只是换个静默失效。
- 图二上三条 `Cannot read properties of undefined (reading 'kind')` 是 v4.1 已修的历史错（`:1674-1690` 现有正确 `return next()`），保留为对照，不再复现。

### ③ 踢人失效
- `client\client.js:1405-1411`：✕ 按钮 `onClick` 里 `:1408 const reason = window.prompt(...)`，`:1409 if (reason === null) return;` ⇒ 该 API 不可用时拿不到面板/返回 null ⇒ 无任何请求、无任何反馈 = 用户看到的“功能失效”。
- 宿主路由 `index.js:2177-2202`（kick）本身完好：`resolveMember` → 删成员 → `appendSystem('… 已被移出会议室')` → `notify===true` 时先 `host.activate` 再 relay → 回 `{removed, notified, members}`。**不需要改宿主**。
- 同类站点共 5 处（同一 API、同一失效模式）：`client.js:1221`（驳回原因·必填）、`:1361`（再议原因·可选）、`:1408`（踢人理由·可选，prefill `view.kickReason`）、`:1544`（散会标题·可选，默认「会议已散会」）、`:1694`（驳回原因·必填）。

### ④ 页头两个 chip
- `client.js:1160-1176` 页头：`:1164` `${room.liveCount}/${room.memberCount} 人`、`:1165-1170` 记录员 chip（builtin ⇒「记录员（内置 AI）」/ 否则「记录员：…」/ 缺失 ⇒「未指定记录员」警告 chip）⇒ 删除 `:1164-1170` 即可，`:1161-1163`（标题/进行中/已归档）、`:1171` spacer、`:1173` 会议文件、`:1175` ← 会议室列表、`:1176` 策划会议 全部保留。

## §2 设计（最小改动）

### ① 用户消息永不进入与会者会话
宿主 `index.js`：
1. `:29` → `const PUSH_MODES = new Set(['off', 'notice']);`（移除 `'full'`）。`:422` 归一化钩子保持不变 ⇒ 已存 `full` 的房间载入即变 `off`（与「默认谁都别被打扰」一致）。
2. `:2118-2120` 改为：
   ```js
   let mode = String(body.mode ?? '');
   if (mode === 'full') mode = 'notice';            // v6：老客户端兜底，正文绝不外发
   if (!['archive', 'notice'].includes(mode)) mode = '';
   if (!mode) mode = 'archive';                      // v6：用户消息默认只归档，不再跟随房间 push
   ```
   `:2132-2142` 的投递段与 `:2135` 的 `pushAll` 目标分支保持不变（`mode==='archive'` 时不投递）。
3. `deliver()` **不改**：`full` 分支仍供《会议结果》`index.js:2446` 与 agent 互发 `:2719` 使用；用户路径已不可能传入 `full`。

客户端 `client\client.js`：
4. `:30` `PUSH_MODES` 与 `:32` `PUSH_LABEL` 一并删除（删后必须 `grep` 确认零残留引用）。
5. `DrawerDelivery`（`:1500-1520`）去掉三档按钮与三行档位说明，改成固定的两条说明：
   - 「你发的消息只会写进会议室记录，**不会**出现在与会者的对话里。」
   - 「要他们回应时，点消息区上方的「唤醒与会者」：只会发一行『会议室有新消息』，不含你的正文。」
6. composer 提示行 `:1244` 改为固定文案：`你的消息只留在会议室记录里，不会进入与会者对话；需要他们回应时点「唤醒与会者」。思考程度：${REASONING_LABEL[...]}（在「策划会议」里改）`。
7. `:1412-1418` 的「唤醒与会者」按钮**保留**：它显式 `POST /post {text:'（提醒）请在会议室里查看新消息。', mode:'notice'}`，投递内容是插件生成的一行，不含用户正文。
8. 复核 `submit()`/`sendPost()`（约 `:1104-1130`）发帖 body **不含** `mode`/`pushAll`。

### ② 修 `pickEffort` 的 ctx 访问与 async 契约
`index.js:1649-1665` 改为：
```js
async pickEffort(provider, model, level) {
  const llm = this.host.ctx.get?.('llm');          // 与 index.js:757 同法：受限代理只用 get()
  if (!llm?.resolveModelInfo) return null;
  let info = null;
  try { info = await llm.resolveModelInfo(provider, model); } catch { return null; }
  const efforts = info?.reasoning?.efforts;        // 其余逻辑逐字保留
  ...
}
```
`:1701` 改为 `const effort = await this.pickEffort(resolved?.provider, resolved?.model, active.level);`。
`inject` 数组**不动**（仍 `['tools','webServer','agents']`，保持惰性获取，避免激活顺序变化）。

### ③ 5 处原生输入框 → 插件自带面板
客户端新增一个可复用对话框（状态挂在既有的 `view` 对象上，随 `emit()` 重渲染）：
- `view.dialog = null | { title, hint?, value, placeholder?, required?, confirmLabel?, onOk(value) }`（默认 `null`）。
- 渲染位置：`RoomPanel` 返回值里与 `h(Toast)` 并排（`:1247` 附近）加 `view.dialog ? h(Dialog, { view }) : null`。
- `Dialog` 结构：复用 `S.overlay` + 居中卡片（`S.box`），标题 + 可选说明 + `input`（`autoFocus`，`autoFocus` 不可用时靠 `useEffect` 聚焦）+「取消」/「确认」按钮；`Enter` 提交、`Escape` 关闭；`required` 且 trim 后为空 ⇒ 就地显示「必填」提示且**不**执行 `onOk`；确认后 `view.dialog = null` 再 `onOk(value)`。
- 辅助函数 `askText(view, {…}, emit)` 供 5 处调用；5 处的业务回调（POST body、toast 文案）**逐字保留**，只把取值来源从 `window.prompt` 换成对话框回调。
- 收敛判据：`grep -n "window\.(prompt|confirm|alert)" client.js` = 0；`node --check` exit 0。
- 踢人链路照旧：确认 ⇒ `postJson('/rooms/:id/kick', { sessionId, reason: value.trim() || undefined, notify: true })` ⇒ toast「已踢出」⇒ 刷新后成员从名单消失。

### ④ 删页头两个 chip
- 删除 `client.js:1164-1170` 整段（在线人数 chip + 记录员 chip 的注释与三元）。删后 `grep` 确认 `S.chipWarn` 若无其它引用则一并清理，`S.chip` 若仍被「已归档」等使用则保留。
