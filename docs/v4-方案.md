## 1. 六条需求 → 实施方案

### ① 设置 / 新建会议室 / 会议室 合并为一个入口，不再各占左侧菜单

现状（`client/client.js`）：`desiredMain()`（:642-664）与 `applyRoomRows()`（:625-638）把 `PANEL_ID`、`NEW_ID`、`SETTINGS_ID`、分类组 id、`ARCHIVE_ID`、每个房间 id **都**注册进 `sidebar.panellist`。而官方 shell 把 `sidebar.panellist` 的每个条目渲染成**左侧图标栏的一个图标按钮**（证据：asar `dsh/node_modules/@deepseek-ai/dsh-client-ui-sidebar/lib/client.js:174-201`，`panelGlyph` + tooltip，点击 `selectPanel(id)`）——所以现在左侧出现了「设置」「会议 (2)」等冗余图标。

方案（客户端半区）：

- `sidebar.panellist` **只注册 1 个**：`{ id: 'dsh-meeting-room', order: ENTRY_ORDER, label: () => '会议室' }`，图标沿用 `RoomIcon`。
- `main` 注册 1 个面板：`{ key: 'dsh-meeting-room', label: () => '会议室' }` → 新组件 `MeetingWorkspace`。它内部布局：左子栏（房间树：分类可折叠 + 「已归档」组 + 「＋ 新建会议室」+「设置」入口）+ 右内容区（选中房间的聊天，或概览，或《会议结果》）。
- 删除 `NEW_ID`/`SETTINGS_ID`/`ARCHIVE_ID`/分类组 id/房间 id 在 `sidebar.panellist` 的注册；`meeting.activeRoom` 等仍留在内存 state，切换房间 = 换内部视图 + `pullRoomSoon(roomId)`，不再注册/注销任何槽位（顺带消灭每 1.5s 重注册的抖动来源 `applyRoomRows`）。
- 《会议结果》页**不走** `sidebar.right.pane.tab`，而是 `main` 的 keyed 整页 `{ key: 'dsh-meeting-room:result:<roomId>' }`（每个有结果的房间一个）——这一迁移 v2 就已定案并有硬证据：直接 `slots.register({name:'sidebar.right.pane.tab'})` 不会显示，它必须先 `ctx.sidebarRightTabs.register(...)` 注册类型再由宿主打开页签（见 `docs\v2-API.md:212-214` 的 C-2/C-3/C-4）。v2 需求⑦「.md 放侧边栏」的实质（结果 .md 落盘、GUI 里可看、可审核）保留。
- 面板内「返回会话」按钮继续调 `layout.selectPanel(null)`（`client.js:495` 已有）。

验收：`cordis_inspect_query` client/Slots `listSubTree` 里，来自本插件的 `sidebar.panellist` occupant 恰好 1 个；`main` 里来自本插件的 occupant = 1 个面板（key `dsh-meeting-room`）+ N 个结果整页（key `dsh-meeting-room:result:<roomId>`）；没有裸房间/分类/设置/新建的侧栏行。

### ② 点左侧入口 / 房间，右侧直接出内容，不必先点「会话」再展开会话列表

方案：唯一入口被点由官方 shell 自动 `layout.selectPanel('dsh-meeting-room')`（契约 `layout.selectPanel(panelId: MainPanelId | null): void`，asar `dsh-client-ui-layout/lib/client.js:463`、`dsh-client-ui-sidebar/lib/client.js:484-487`）。面板内点房间行 → 直接切换右内容区（内部 state），不需要任何侧栏展开动作。

- `followActive()`（`client.js:705-728`）改为只跟踪我们自己的 key（面板 + `dsh-meeting-room:result:` 前缀的整页），删除为「会话」菜单做联动的分支。
- 房间行与「会议结果」行都渲染在**我们自己的面板内**，点击 = `openRoom(roomId)` / `openResult(roomId, goalId)`，后者把 `meeting.subview='result'` 并在面板内渲染，必要时再 `selectPanel` 到结果整页。

验收：逻辑层断言（面板内 state 切换即可渲染房间内容）+ Slot 树断言；**真机点按观感由用户目视**（agent 无法看屏幕，如实标注未核实）。

### ③ 「策划会议」等界面颜色与主 UI 一致

根因：`client.js:113`（`menu`）与 `client.js:117`（`sheet`）用了 `var(--surface-primary, #fff)`；`sheet` 在浅色主题下是白底，而输入控件（`:69-71`、`:90`）用 `color:'inherit'` → 白底白字。

方案：全部改用 rc.1 官方主题 token（`cordis_inspect_query` client/Theme `listTokens` 实证存在）：

| 用途 | token |
| --- | --- |
| 面板底 / 应用底 | `--dsw-alias-bg-layer-1` / `--dsw-alias-bg-base` |
| 次级嵌套面 / 消息气泡 | `--dsw-alias-bg-layer-2` |
| 抽屉、菜单、浮层 | `--dsw-alias-bg-overlay` |
| 主/次文字 | `--dsw-alias-label-primary` / `--dsw-alias-label-secondary` |
| 主边框 / 强边框 | `--dsw-alias-border-l1` / `--dsw-alias-border-l2` |
| 品牌色（我发的消息、主按钮） | `--dsw-alias-brand-primary` |
| 成功/警告/错误/空闲 | `--dsw-alias-state-success-primary` / `-warn-` / `-error-` / `-idle-` |
| 侧栏条 | `--dsw-specific-sidebar-fill` |

- 删除所有 `var(--surface-primary, #fff)` 与硬编码 `#fff`（含 `S` 表里的裸白）。
- 输入类控件（`inlineInput`/`select`/`textarea`/`input`）显式 `color: 'var(--dsw-alias-label-primary)'`，`background: 'var(--dsw-alias-bg-layer-2)'`，`border: '1px solid var(--dsw-alias-border-l1)'`。
- 主题切换（浅/深）下都要可读：不允许出现「深色文字 + 深色底」或白底白字。

验收：`grep -n "#fff\|surface-primary\|color: 'inherit'" client/client.js` 命中 0（`inherit` 允许出现在明确继承文字的容器上，桩里逐条说明）；风格常量表内每个颜色都是 token。

### ④ 记录员 = 每个房间自带的内置 AI，不由用户指派；平时不发言不思考

方案（宿主半区 `index.js`）：

- 房间不再有「记录员 sessionId」。`room.summary()` / `state` 里的 `recorder` 字段固定返回 `{ kind: 'builtin', label: '记录员' }`。
- 路由 `POST /rooms/:id/recorder` 保留但恒 `400 { error: 'v4：记录员是每个会议室自带的内置 AI，不需要指派' }`（保留路由是为了让旧客户端拿到明确中文，而不是 404）。
- 内置记录员**不注册 agent、不进 members、不接收任何投递**，「平时不发言不思考」。
- 目标达成时由内置记录员产出草稿：`POST /rooms/:id/goals/:gid/complete` 成功后，宿主调用 `ctx.get('llm').stream({ provider, model, system, messages, temperature: 0.2 })` 生成《会议结果》正文，写入 `result.status='draft'`、`result.by='记录员'`、`result.body`，并在 `result.evidence` 记录引用的 transcript `seq` 范围（**不得无中生有**：提示词必须写明「只能依据给定记录，缺证据就写『记录中未涉及』」）。
  - provider/model 解析顺序（每步都要 try/catch + 明确失败文案）：`ctx.get('agentDefaultModel')?.currentSelection()`（先 `cordis_inspect_query` host/Service 确认方法名）→ `llm.listProviders()[0]` + `llm.listModels(provider)[0]`（确认签名）→ 失败则 `fail(503, '内置记录员暂时无法调用模型（…）：可以手动填写《会议结果》')`，房间状态保持 `pending`、不写半成品。
  - 生成过程要幂等：同一目标重复 complete 不重复追加草稿；已 `approved` 的目标不再重生成。
- 生成仍是**草稿**，必须用户在客户端审核 `approve`/`reject`（v2 需求⑦的人工审核步骤不能省）。
- 客户端：去掉『指派记录员』UI，记录员 chip 显示「记录员（内置 AI）」；点「标记达成」后显示「记录员正在整理…」（轮询自然刷新），失败时显示中文原因。

验收（宿主探针 + selftest）：`recorder.kind==='builtin'`；`POST /rooms/:id/recorder` → 400；假 `llm`（返回固定两段文本）下 complete → `result.status='draft'`、`body` 非空、`evidence.seqFrom/seqTo` 落在真实 transcript 范围内；`llm` 缺失 → 503 且 `result` 仍为 `pending`、无残留文件；记录员不出现在 `members`。

### ⑤ 「邀请与会者」列表必须是真会话名（用户标注：最重要）

现状：宿主 `GET /dsh-room/sessions` 把**全部**会话都返回（真机 69 条），其中 43 条是 `origin='subagent'` 的子会话，标题是 `<system-reminder> You are teammate …` 这类 prompt——所以用户看到的「不是会话名」。真名读取已在 rc.1 修复（`index.js:1288-1296`），现在要做的是**只列顶层会话**。

方案（宿主半区）：

- `/sessions` 过滤掉：`header.origin === 'subagent'`、`header.parentSession != null`、`(header.delegationDepth ?? 0) > 0`、`header.isSeeded === true`。
- 每项返回 `{ sessionId, title, cwd, live, persisted, updatedAt }`；排序：`live` 优先，其次 `updatedAt` 倒序（没有 `updatedAt` 用 `header.createdAt`）；`title` 沿用已修的 rc.1 快照读取，取不到才回落 `会话 <前 8 位>`。
- 额外返回 `{ total, filtered }`（过滤前条数 / 被过滤条数）便于排查；提供 `?includeSubagents=1` 只给内部调试用。
- 客户端半区：邀请列表主标题 = `title`，副标题 = `basename(cwd)`，右侧 `在线/离线` 徽章；已在房间内的会话按钮显示「已在房间」且不重复 join；空列表给中文说明。

验收：假宿主构造 3 条顶层 + 2 条 subagent（带 `parentSession`/`delegationDepth`），断言 `/sessions` 只返回 3 条且无 subagent 字段；真机 live 复核：69 条 → 过滤后约 27 条，每条 `title` 是用户可辨识的真名（不是 `system-reminder…`）。

### ⑥ 聊天页：去方框、用户消息靠右、与会者名字分色

现状：`S.msg`（`client.js:81`）带 `border: 1px solid LINE` → 每条消息一个框；渲染处（约 `:1180-1220`）没有左右对齐；`S.who_user`（:83 蓝）/`who_agent`（:84 绿）/`who_system`（:85 灰）固定三色。

方案：

- 消息行去掉 `border`，只保留 `padding` 与间距（`padding: '4px 2px'`、`gap: 2`）。
- `kind === 'user'`（我发的）→ 整行靠右、气泡底色 `--dsw-alias-bg-layer-2`、圆角 10、`maxWidth: '78%'`；其它 → 靠左、无底色或极浅底色；系统行居中/左对齐灰色斜体。
- 与会者名字按稳定哈希取调色板（`--dsw-alias-brand-primary`、`-state-success-`、`-state-warn-`、`-state-error-`、`-state-idle-` + `--dsw-alias-label-secondary`），同一个 label/sessionId 恒定同色；名字与时间放气泡上方一行。
- 时间戳用小号 `--dsw-alias-label-secondary`。

验收：`S.msg` 无 `border`；渲染断言（既有 `node:vm` 客户端探针）：user 行右对齐、agent 行左对齐、同名两次颜色一致、至少 3 种不同名字得到 ≥3 种颜色。
