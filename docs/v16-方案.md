## 1 取证

### 1.1 ⑦ 的三组数字是宿主投影，原生组件不能复用
- `dsh-session-stats/lib/types/projection.js`：`sessionStatsSchema = {turns, steps, llmMs, toolMs, ttftMs, ttftSteps, decodeMs, decodeTokens}`。
- `dsh-token-meter/lib/types/usage-projection.js`：`tokenUsage` 视图 = `{uncachedInputTokens, outputTokens, cacheReadTokens, cacheWriteTokens}`；`contextPressure` 视图 = `{contextWindow?, pressureTokens?, projectedTokens?}`，其中 `pressureTokens = input + cacheRead + cacheWrite`（prompt 侧，不含 output），`projectedTokens = max(0, pressureTokens + surfaceTokens - sampledSurfaceTokens)`。
- DSH 底栏口径：缓存命中率 = `cacheRead / (未缓存输入 + 缓存读 + 缓存写)`；tok/s = `decodeTokens / (decodeMs/1000)`；圆环 = `min(100, round(used / contextWindow * 100))`。
- 原生 `StatsPills`（`dsh-client-ui-chat/lib/client.js:7130-7178`）是包内私有 const，**不能 import**；客户端也不该为这个去碰未验证的 `sessions` 服务。⇒ 由宿主算、随 `members` 一起下发。

### 1.2 ③(a) 注入守则的正规途径（子代理调研报告 `%TEMP%\mr-prompt-report.md`）
- 首选：在该 agent 作用域 ctx 上 `systemPrompt.section({name, order, text})`。
  - `dsh-system-prompt/lib/index.js:240-243` 的 `section()` 走 `this.layers.effect(this.ctx, …)`，而 `dsh-agent-loop/lib/index.js:778-779` 里 `agent.ctx = createScope(loopCtx, agent).ctx` ⇒ 挂在 `agentCtx` 上就是「只对这个 agent 生效」。
  - `dsh-scope/lib/index.js:189-192` 的 `scopeOf(ctx)` 决定落层；官方文案（`dsh-system-prompt/lib/index.js:190-192`）也写明 per-agent override 走 `agent.ctx`。
  - `SystemPromptProjection.project()` 有 `if (latest.text === rendered) return [];` ⇒ **恒定文本只落一次**，不会膨胀历史。
- 否决项（别再找）：`agent/request` 不能改消息；`create()/resume()` 没有守则字段；`agent/pre-step` 只能插 **user** 消息；`AGENTS.md` 没有 per-session 参数且会污染整个目录的所有会话。

### 1.3 ⑥ 真机取证：影子工具根本没接管（子代理报告 `%TEMP%\mr-desktop-report.md`）
1. 暂存区 `%TEMP%\dsh-meeting-room` 存在但**空的**（0 子项，mtime 早于全部会议写入）。
2. 实验 3 会话 `seq=155` 用**裸顶层相对名** `实验3-预注册-授权三格.md` 调 `write`（影子唯一会拦的形状），`seq=156` 工具结果逐字 `<path>C:\Users\uyiop\Desktop\实验3-预注册-授权三格.md</path> … Created file` ⇒ 一个字都没改道。

### 1.4 ⑤ 系统文件夹界面（子代理报告 `%TEMP%\mr-picker-report.md`）
- 最佳：preload 注入的 `globalThis.__DSH_DIRECTORY_PICKER__.pick()`（`dsh-app://app` 窗口，取消回 `null`）。

## 2 实现（全部最小改动，无新增端点以外的接口变化）

### 2.1 ① 回到最底图标（`client/client.js`）
`RoomPanel` 里原来的条件是 `!following && hasNew ? h('button', …)`（只有「有新消息」时才出现）。
v16① 改成 **不跟随时常驻**：`!following ? h('button', { style: hasNew ? { ...S.toBottom, ...S.toBottomNew } : S.toBottom, title: hasNew ? '有新消息，回到最底' : '回到最底' }, '↓')`。
跟随/停止跟随的判定逻辑（`nearBottom`、`programmatic` 800ms 窗口）**一字未动**，避免破坏 v13③ 的跟随语义；`S.toBottomNew` 是新增样式（主题色描边）。

### 2.2 ② 草稿编辑器（`client/client.js` 结果抽屉）
根因是标题输入框复用了 `S.inlineInput`（`flex-basis: 120px`）把标题撑成一大块，正文 `textarea` 只有 8 行。
现在：标题 `style:{...S.inlineInput, flex:'0 0 auto'}`；正文 `style:{...S.textarea, flex:'1 1 auto', minHeight:260, lineHeight:'18px'}, rows:14`。

### 2.3 ③(a) 与会者守则 `CONDUCT_PROMPT` + `installConduct()`（`index.js`）
- `CONDUCT_PROMPT` 五条：围绕目标讨论 / 有依据再下结论 / 达成共识就用 `room_goal_report`（整个目标完成用 `room_task_done`）/ 小步前进发言简短 / 会议文件用 `room_say` 的 `files` 交接。
- `installConduct(agentCtx, rec)` 在 `EffortControl.ensure()` 注册完 `agent/request` 之后调用：取 `agentCtx.systemPrompt ?? agentCtx.get?.('systemPrompt')`，拿不到 `section` 就 `rec.conduct='none'` 静默返回（**守则注入失败绝不影响会议**）；成功则 `section({name:'meeting-room:conduct', order:700, text: CONDUCT_PROMPT})` 并把 disposer 收进 `rec.disposers`（agent 换代时一起释放），`rec.conduct='on'`。

### 2.4 ③(b) 驳回后立刻重议（`index.js` 审核分支）
驳回原本只把 `result.status` 改回 `'draft'`、写 note、`appendSystem`，**不给任何人投递**。
现在追加 `rejectText`（草稿被驳回 + 会议目标 + 驳回原因 + 「请逐条回应驳回原因」+ 用 `room_goal_report` 反馈），并
`await room.deliver({ text: rejectText, kind:'reject', authorLabel:'审核意见', targets:[...room.members.keys()], mode:'full', latestSeq: room.seq })`（try/catch，失败只 `host.warn`），返回体加上 `delivered/failed`。

### 2.5 ③(c) 记录员提示词（`DEFAULT_RECORDER_PROMPT`）
新增第 5/6/7 条：只记最终共识、分工与待办（讨论过程/来回辩驳/被否决方案不写，分歧只在「未决问题」一句话点出）；不得编造、不替人补观点、不把单方长篇当共识（只有被接受/无异议才算共识）；简洁，能写清单就不写段落。

### 2.6 ④⑤ 会议列表分组与目录选择（`client/client.js`）
- ④ 分组头新增「＋」按钮：`onClick` 记 `meeting.createCategory = group.category || ''` 再开新建对话框，新房间目录就建在该分组文件夹下（复用原 `defaultCategory` 通道，宿主侧零改动）。
- ⑤ 新建对话框里的「换分类目录」不再切到浏览式，改调 `chooseCategory()`：`await pickSystemFolder()` → 拿到绝对路径就用它，拿不到（`undefined`）才退回原来的 `DirPicker` 浏览式兜底。

### 2.7 ⑥ 文件落盘：三层兜底（`index.js`）
**第 1 层（v14 原有，真机未生效）**：同名影子工具（`write/edit/read/read_image`）在 agent 作用域把顶层文件名改写到暂存区。保留原样，但现在**不再静默**：`rec.tools = installed > 0 ? 'on' : 'none'`。

**第 2 层（v16⑥ 新增，事件驱动）**：
- `expect()` 里 **投递即开窗** `openWindow(rec, room, agent)`：记 `{room, dir, cwdRoot, startedAt, baseline(=readdir(cwdRoot) 快照), moved}`（不再只等 `agent/inbox/inserted`）。
- `tools/post-execute`（waterfall，`register()` 包 try/catch）→ `collectExec()`：只认 `write/edit`，从 `exec.arguments/args` 里取 `file_path|filePath|path`；`stageTopLevelName()` 判定「是不是会话 cwd 的顶层文件」（相对名、`.\x`、以及**绝对路径的父目录正好是 cwd** 都算），是就把产物 `relocate()` 进暂存区。
- `agent/turn-stopping` → `collectLeftovers()`：拿开窗快照做**差集**，把本轮新建的顶层文件一并搬走（**这条覆盖 `pwsh` 等非写工具**），然后 `flush(room)` 同步进房间「附件/」。
- `relocate()`：`mkdir + copyFile` 进暂存区；只对「本轮新建」（快照里没有）且非 `edit` 的文件 `rm` 原件 —— **与会者改用户既有文件时只取副本，绝不删用户自己的东西**。
- 注册失败只 `warnOnce('hook:<事件名>')`，不影响会议。

**第 3 层（v16⑥ 兜底，完全不依赖 agent 钩子）**：`sweepSession(room, sessionId)`
- 在**两个必然发生的巡检点**调用：`room_say` 交作业时（刚写完的文件就在那儿）、以及每次给某成员投递（唤醒它）之前（顺手收拢它上一轮的产物）。
- 逻辑：取该会话 `cwd` → 与 `lastSweep.get(sessionId)`（上次巡检时间）比 `mtime` → 只对「上次巡检之后新建/改动」的顶层文件 `relocate()`（走同一套 copy + move）。
- **首次只立基线、绝不搬任何文件**（避免动会议开始前就存在的桌面文件）。
- 因此即使「没有 agent 作用域、拿不到钩子、影子完全失效」，文件照样会在下一次巡检时被收进「附件/」并移走。

**诊断端点**：`GET /dsh-room/staging` → `{ root, stageTools, members:[{sessionId, tools, conduct, pending, activeRoom, cwd, movedInWindow}], swept, events(最近 50 条搬运流水) }`（只读，不碰任何状态）。重载 DSH 后靠它一眼判断「是影子没注册上，还是开窗没生效」。

**提示文案**：`fileHint` 改成与实现一致的说法 —— 「直接以相对文件名保存即可 …… 写在工作区顶层的文件，插件会在这一轮结束时收进 <附件目录> 并从原地移走；不要写到工作区以外的地方。」

### 2.8 ⑦ 底栏数字（宿主算 + 客户端排版）
- 宿主 `MeetingHost.statsFor(sessionId)`（4 秒短缓存 `STATS_TTL = 4000`）→ `computeStats(sessionId)`：`ctx.get('sessionProjections')` + `agentOf(sessionId)?.session`，`snapshot(session, ['sessionStats','tokenUsage','contextPressure'])`，算出
  `turns / steps / totalTokens(=未缓存+缓存读+缓存写+输出) / outputTokens / cacheReadTokens / cacheHitPercent / tokensPerSecond / contextUsed / contextWindow / contextPercent`；**任一步失败返回 `null`**（数字不影响会议）。
- `Room#membersView()` 每人加 `stats` ⇒ 客户端 `RoomStats` 收到就能显示；没有 `stats` 的成员被过滤，**整条数字栏在完全拿不到数据时不渲染**（不显示假数字）。
- 客户端 `RoomStats`：汇总 `轮次(max) / 步(sum) / 累计 tok(sum) / 缓存命中(按 token 加权的 cacheRead 占比) / 上下文(占用最高的成员)`，鼠标悬停 `title` 里给每人一行 `轮 N · 步 N · X tok · 缓存命中 N% · 上下文 N%`；`formatTokens()` 做 K/M/B 缩写。

## 4 诚实边界（没验证到的，一律写在这里）

1. **⑥ 必须重载 DSH 才可能生效**：真机取证时跑着的宿主是旧版代码（`GET /dsh-room/staging` → 404）。重载后请先 `GET /dsh-room/staging` 看 `members[].tools`：`none` = 影子没注册上（第 2 层失效，但第 3 层巡检仍在），`on` = 影子可用；再看 `events` 里有没有 `kind:'handin'/'sweep'` 的搬运流水。
2. **⑥ 只覆盖「会话 cwd 的顶层文件」**：写到子目录（`Desktop\子目录\x.md`）或 cwd 之外的位置**不会**被搬走 —— 这是有意的（否则会误搬用户的项目文件）。
3. **⑥ 的「移走原件」只对「本轮新建」的文件生效**：改用户既有文件时只往附件留副本、原文件保留（宁可不搬，也不删用户的东西）。
4. **⑦ 依赖 `ctx.get('sessionProjections')` 在插件 ctx 上可用**：拿不到就整条数字栏不显示（不编造数字）；真机上要实测确认。
5. **③(a) 注入瞬间会让该会话的 system prompt 变一次**（缓存全量重付一次，之后恒定应恢复）；`agentCtx.systemPrompt` 能不能直接读到、`agentPresets` 会不会压掉 section，都需要真机确认（拿不到就静默降级）。
6. **① 的「小图标」在跟随时不显示**（跟随时本来就在底部，不需要）；这是照用户「上滑浏览时出现」的原话。
7. ⑤ 的系统文件夹界面在**纯浏览器**里应为 `undefined`，会自动退回房间内浏览式 —— 这是设计好的两级降级，不是 bug。
