# v14 方案：会议文件自动收进「附件/」（桌面零残留）/ 文件管理简化 / 消息索引改成轮次刻度

> 用户原文（User said, m02954，**摘意**，逐字原文见会话记录）：
> ① **会议讨论时产生的文件还是落在我的桌面上**——v13 只是在唤醒消息里叫 AI 别写桌面，不管用；要真的收进会议文件夹。

## §0 取证：v13 的「文件写哪」提示为什么必然失效

### 0.1 与会者会话的 cwd 就是桌面，而沙箱只许写 cwd + 临时目录

- 与会者会话是普通 DSH 会话，`SessionHeader.cwd` 创建后不可改（`dsh-session/lib/types/index.js:68` 深冻结 + `:45-51` 绝对路径校验；磁盘目录名由 cwd 派生，`dsh-workspace/lib/index.js:114-123` 还会校验 header 与 workspace 一致）。本机所有会话（含与会者）的 cwd 都是 `C:\Users\uyiop\Desktop`。
- 沙箱：`dsh-fs-sandbox/lib/index.js:142-166 checkedTarget` 对 target **重新 realpath** 后必须落在 `writableRoots(policy)` 内，否则抛 `cannot write "...": file access denied under workspace-write mode`；`dsh-sandbox/lib/index.js:158-173 writableRoots(policy)` 对 `workspace-write` 给出 `[policy.workspaceRoot, '/tmp', os.tmpdir()]`；`policy.workspaceRoot` 恒等于会话 cwd（`dsh-sandbox-policy/lib/index.js:141-148`）。
- **实测取证**：解压与会者会话日志 `~/.dsh/sessions/--C-Users-uyiop-Desktop--/session-90790f5e-…/session.v4.jsonl.zstd`（多 zstd frame，按 magic `28 B5 2F FD` 逐帧解压）可见 `{"type":"permission/preset","data":{"preset":"workspace-write"}}`、`{"type":"sandbox/mode","data":{"mode":"workspace-write"}}`、`{"type":"approval/policy","data":{"policy":"ask"}}`，以及系统提示 `Current DSH file policy: workspace-write. Any available operation enforced by the DSH file sandbox may modify files under the session workspace: …`。
⇒ **v13 让 AI「把文件写在 `<房间目录>\附件`」这条指令在 workspace-write 下根本执行不了**（房间目录在 `C:\Users\uyiop\dsh\会议\…`，不在 cwd 内、也不是 temp）。AI 要么被沙箱拒，要么按老习惯写桌面 ⇒ 用户看到的还是「文件堆在桌面」。这不是措辞问题，是通路问题。

### 0.2 为什么不能用「改参数」的正规钩子

- `tools/pre-execute` 只能 allow / deny / ask / cancel，**不能改参数**：参数在派发前已经 `deepFreeze`（`dsh-tools/lib/index.js:2609 return deepFreeze(detached);`），官方 README:230 原文「`tools/pre-execute` deliberately cannot rewrite `exec.arguments` —— logged and rendered args would desync from what ran」。`tools/execute` 那条 waterfall 也只允许改 `exec.signal`。
- 想让与会者「写去别处」，就只剩两条路：
  - **per-agent scoped tool shadow（本版采用）**：`dsh-tools/lib/index.js:2878-2887 register(definition)` 注释「Register globally or in the calling agent scope. **Scoped tools shadow globals**」；`:2959-2985 view(scope)` 先 globals 后 scope 覆盖；`:2634` 的重复注册报错文案本身就推荐「for a per-agent variant, register through that agent's `agent.ctx`」。agent 作用域 ctx 由 dsh-agent-loop 建（`dsh-agent-loop/lib/index.js:748,756-757 this.scope = createScope(loopCtx, this); this.ctx = this.scope.ctx`），插件已经在它上面挂过钩子（EffortControl）。
  - 拒绝方案：`agents.create({sessionId, meta:{cwd}})` 只能给**新会话**设 cwd（已存在的与会者会话换不掉，`dsh-api-session-controller/lib/index.js:208-210 resolveAgent(sessionId)` 单参数）；`setSandboxMode` 提权会持久化改用户会话的安全档位，禁用；覆写 `{{cwd}}` 提示变量属于动 DSH 本体，禁用。

### 0.3 于是 v14① 的形状被约束死了

与会者的顶层文件**只能先落在一个「它写得进去的地方」**（会话 cwd 根目录，或 `os.tmpdir()`），再由**插件自己**搬进房间 `附件/`。v14 选 **`os.tmpdir()/dsh-meeting-room/<roomId>/` 当暂存工作区**：

- 任何 sandbox 模式下 temp 都可写（read-only 除外——那种模式下与会者本来就什么都写不了，与插件无关）；
- 桌面 0 残留（连临时文件夹都不放桌面）；
- 插件是宿主进程，搬文件不受与会者沙箱约束。

### 1.2 `class MeetingStaging`（`index.js:2024-2173`）

- `dirFor(roomId) = join(STAGING_ROOT, safeName(roomId,'room'))`、`warnOnce(key,text)`。
- **`expect(room, agent, rpcId)`**（`:2042`）：投递前登记「这条 rpcId 触发的那一轮属于这个房间」。接线点在唯一投递漏斗 `relayWithEffort`（`index.js:1656`，**在思考等级判断之前**，与 `reasoning` 设置无关）。
- **`ensure(agent)`**（`:2051`）按 agent 缓存（WeakMap），挂两枚钩子：
  - **`agent/inbox/inserted`**（`:2065`）：`payload.message.source.rpcId` 命中 `pending` ⇒ 删 pending 并置 `rec.active = {room, dir, cwdRoot: agent.session?.header?.cwd}`；**没命中（人类正文 / 非会议投递）⇒ `rec.active = null`**（绝不在非会议轮改写路径）。消息进箱发生在 `agent.followup()` 那一刻（`dsh-agent-loop/lib/index.js:206`），必然早于本轮任何工具调用。
    - **故意不用 `agent/pre-step`**：那是 EffortControl 也在用的 waterfall（`index.js:1940`），再挂一枚会让既有护栏「同一 agent 只注册一枚 pre-step」失真，也多一份 `next()` 契约风险。
  - **`agent/turn-stopping`**（serial，`:2080`）：本轮结束 ⇒ `rec.active = null` 并 `flush(room)` 把暂存区同步进 `附件/`。
- **`installShadows(agentCtx, rec)`**（`:2099`）：**只在 `agentCtx.tools`（该 agent 作用域）**上 `register` 同名影子工具；拿不到 `tools.register/get` 就 `warnOnce` 降级成「只提示、不接管」（**绝不全局注册**，否则污染所有会话）。`base = tools.get(name)` 取的是全局基准定义（`get(name, scope)` 不传 scope 只返回 globals，不会被自己的影子套娃）。
- **`rewrite(name, args, active)`**（`:2135`）：
  - `write`：**一律**改写 ⇒ 桌面上的同名旧文件不会被覆盖（AI 的版本进会议文件夹，用户的原件不动）；
  - `edit` / `read` / `read_image`：**暂存区真有同名文件才**改写（读写同一份工作副本），否则照原样读桌面上的真文件 —— 不劫持用户自己的文件。
- **`flush(room)`**（`:2148`）：`readdir(暂存区)` → 每个文件 `copyFile` 到 `room.attachmentsDir`（**同名覆盖**：暂存区永远是最新版本）+ `host.refreshFiles(room)` 让面板文件列表立刻出现。
- **`clear(room)`**（`:2169`）：`rm -rf` 暂存区（产物已在 `附件/` 里，暂存区只是工作副本）。

### 1.3 三处接线

1. **唤醒消息的「文件放哪」改成可执行的指令**（`index.js:829-831`）：只在**本来就用 `room_say`** 的那条唤醒消息里追加
   `\n（本次会议的文件直接以相对文件名保存即可，例如 报告.md —— 插件会自动把它们收进 <附件目录>；不要写到桌面根目录或其它地方。）`
   （旧文案叫 AI「写在 `<房间目录>\附件` 里」，在 workspace-write 下写不进去 —— §0.1。）
2. **`room_say files` 的相对名回落查暂存区**（`index.js:1858-1867`）：相对名在「附件/」和 `process.cwd()` 都找不到时，若暂存区有同名文件 ⇒ 先 `flush` 再返回同名 ⇒ 不会复制出 `报告-1.md` 那种重名副本。
3. **散会前先收再清**（`index.js:2724-2726`）：`close` / `adjourn` 分支在 `room.cleanupAttachments()`（recorder 模式清空附件）**之前** `flush` + `clear`，否则最后一份产物会留在 temp 里。**《会议结果》发布分支故意不动**（会议可能还在继续，附件要继续收）。

### 1.4 自测怎么钉住它（`selftest/run.mjs` 的 `v14① 会议文件暂存区…` 段，19 条）

- 只在与会者 agent 作用域注册 **4 枚**影子工具（根 `host.tools` 上**没有** `write`/`read`/`read_image`）；挂 `agent/inbox/inserted` + `agent/turn-stopping` **各一枚**，`agent/pre-step` **0 枚**（不侵占 EffortControl）。
- `write 报告.md` / `write .\报告.md` → 落在 `<tmp>/dsh-meeting-room/<roomId>/`；`sub/x.md`、`../x.md`、别处绝对路径**原样放行**；会话 cwd 根下的绝对路径 → 暂存区。
- `read` 在暂存区还没有该文件时**不劫持**；人类消息进箱 ⇒ 解除会议作用域后不再改写；造出暂存文件后 `read`/`edit` 命中改写。
- `turn-stopping` ⇒ `附件/报告.md` 内容一致 + 立刻进 `state.files`；无活跃轮时 `turn-stopping` 安全空转；同一与会者再次投递不重复注册。
- `room_say {files:['附录.md']}` → `附件/附录.md`，**没有** `附录-1.md`；散会 → 暂存区清场、产物仍在 `附件/`。

### 1.5 诚实边界（v14① 不做的事）

- **只接管 4 个文件工具**：`pwsh`/`bash` 命令串里的相对路径（例如 `echo hi > 报告.md`）**不拦** —— 命令串不可靠地解析，强行改 `workdir` 反而会打断与会者跑项目脚本。
- **只认顶层文件名**：带目录的相对路径一律放行（§1.1）。会议通常产出的就是一堆顶层文档，这正是「桌面堆文件」的形状。
- 宿主若没有 agent 作用域工具注册能力（`agentCtx.tools` 不可用），自动降级为**只提示**并 `warn` 一次；此时文件仍可能落桌面 —— 这是**已知的降级面**，不是静默失败。
- 与会者会话如果是 `read-only` 而不是 `workspace-write`，它本来就写不了任何地方，插件不会也不能提权。

## §3 v14③④：消息索引改成「普通会话式轮次轨道」

### 3.1 ③ 外形：悬浮、等距、不压滚动条（`client/client.js:114-122`）

| | v13 | v14 |
| --- | --- | --- |
| 定位 | `position:absolute; top:6; bottom:6; right:2; width:16`（贴边、摊满整列） | `position:absolute; right:12; top:50%; transform:translateY(-50%); width:20; maxHeight:420`（**悬浮在右侧中间一段**） |
| 横条容器 | 无（`marginTop` 按真实 `offsetTop` 比例摊开，所以**忽密忽疏**） | `railList`：`display:flex; flex-direction:column; max-height:420; overflow-y:auto`（**固定 10px 一行、刻度多了自己滚**） |
| 刻度 | `mark` 9×2 / 目标 13×3 | `mark` 20×10 的**点击行** + 行内 `markLine` 12×2 横线；目标/当前/悬停改成线宽 20×3 / 20×3 |
| 预览卡 | `right:20` | `right:26`（不压住刻度行） |

### 3.2 ④ 刻度粒度：一个轮次一个刻度（`client/client.js:1594-1598`）

```js
function isTurnHead(message) {
  const message_ = message || {}; const author = message_.author || null;
  return !!((author && author.kind === 'user') || isGoalMark(message_));
}
const RAIL_TICK = 10; const RAIL_MAX_HEIGHT = 420;
```

- 刻度 = `log.filter(isTurnHead)`：**主持人（人类）发言** 与 **目标时间点**（`kind` 以 `goal` 开头 / 带 `goalId`）各算一个轮次头；与会者的连续发言不再各占一格。
- 少于 2 个刻度就整个不画（`shown = ticks.length >= 2 ? ticks : []`，早退条件含 `!shown.length`）。
- 当前刻度 = 最后一个 `seq <=` 视口活动消息的刻度，滚动时自动把它滚到列中间（`el.scrollTop = want`）。
- 点击刻度：`boxes.current[tick.index].scrollIntoView({block:'start', behavior:'smooth'})` + `props.onJump()`（关掉「跟随最新」）。
- 样式只在 `span[data-mark]` 上区分：`goal`（20×3，`--dsw-alias-brand-primary`，op .85）/ `turn`（12×2，`--dsw-alias-label-tertiary`，op .5）；悬停/当前由 `markOn`/`markView` 覆盖。
- **真 bug（本版顺手修掉的一次性坑）**：`RAIL_TICK` / `RAIL_MAX_HEIGHT` 原声明在 `MessageRail` 附近，但样式对象 `S.rail`/`S.railList` 在 `const S = {`（`client/client.js:55`）求值时就要用 ⇒ `ReferenceError: Cannot access 'RAIL_MAX_HEIGHT' before initialization` 会让**整个客户端挂掉**。现已把两常量上移到 `client/client.js:53-57`（`const S` 之前），并留注释。
