## 2. 设计（逐条）

### ① 与会者按需自动激活（host，最小改动）
**语义**：不再要求用户先去那个会话里说一句话；只要**真的要投递**（普通消息或「唤醒与会者」），宿主先把目标会话激活成 live agent，再投递。激活失败则把原因放进 `failed`，不崩、不静默。

1. 在 `MeetingHost` 里新增（放在 `agentOf()` 之后）：
   ```js
   /**
    * v5：按需激活与会者会话。
    * 官方 sessionController.resolveAgent(sessionId) 与 GUI 打开会话是同一条通路
    * （内部 agents.resume + agent preset 组合），返回 { agent } | { error }。
    * 语义：只在真要投递时激活，不主动唤醒任何会话。
    */
   async activate(sessionId) {
     const live = this.agentOf(sessionId);
     if (live) return { ok: true, agent: live, activated: false };
     const controller = this.ctx.get?.('sessionController');
     if (controller && typeof controller.resolveAgent === 'function') {
       try {
         const result = await controller.resolveAgent(sessionId);
         if (result && result.agent) return { ok: true, agent: result.agent, activated: true };
         return { ok: false, error: (result && result.error && result.error.message) || '会话无法激活' };
       } catch (error) {
         return { ok: false, error: (error && error.message) || String(error) };
       }
     }
     const agents = this.ctx.agents;
     if (agents && typeof agents.resume === 'function') {
       try {
         const handle = await agents.resume({ resumeSessionId: sessionId });
         if (handle && handle.agent) return { ok: true, agent: handle.agent, activated: true };
         return { ok: false, error: '会话无法激活' };
       } catch (error) {
         return { ok: false, error: (error && error.message) || String(error) };
       }
     }
     return { ok: false, error: '宿主没有提供会话激活能力' };
   }
   ```
2. `deliver()` 两处改动：
   - `:649` 缺省目标从 `this.liveMembers()` 改为**全体成员** `[...this.members.values()]`（激活才是闸门；否则「唤醒与会者」在全员离线时目标为空、什么都不发）。
   - `:656-658` 循环体开头改为：
     ```js
     const activation = await this.host.activate(member.sessionId);
     if (!activation.ok) { failed.push({ sessionId: member.sessionId, error: activation.error || '会话不在线' }); continue; }
     ```
     并统计 `activated += activation.activated ? 1 : 0`，返回值由 `{ delivered, failed }` 扩为 `{ delivered, failed, activated }`。
3. `POST /rooms/:id/post`（`:2100-2103`）把 `activated` 一并回给客户端：`{ message, delivered, failed, activated, droppedFiles, mode }`。
4. `kick` 的 `notify`（`:2147`）改成先 `await host.activate(target.sessionId)`，成功才 `host.relay(...)`；失败只 `host.warn`，`notified` 仍为 false。
5. **不改** `relay` / `relayWithEffort` / `relayFromAgent*` 里的 `if (!agent)` 保护（激活后自然有 agent；保护留着防竞态）。

**验收（host 侧）**
- 成员会话不 live 时，`POST /rooms/:id/post {text, mode:'notice'}`（**不带 `to`**）→ 回包里 `delivered` 含该 session、`activated ≥ 1`；随后 `GET /rooms/:id` 的 `members[].live === true`。
- 全员离线时「唤醒与会者」（等价于上面这条请求）`delivered.length === 成员数`。
- 传一个不存在的 sessionId 当成员 → `failed` 里有带 message 的条目；进程无异常、无未捕获 rejection。
- `mode:'archive'` 不触发任何激活（`deliver` 不被调用）。
- 拿不到 `sessionController` 时回落 `agents.resume`，同样能投递（可用假 ctx 验证分支）。

5. **`setTimeout(toBottom, 0)` 时机**：若消息节点要等下一帧布局，极端情况下可能差几像素；真实轮询节奏下的「不强制滚」只验了手动拉一拍。
6. **`start()` reject 的原因未知**（见 6.4）；宿主侧无日志。
7. **`.recon-tmp` 宿主副本与 asar 实际加载版本未逐行比对**（除本方案引用的三个文件已用 SHA1 对齐）。
