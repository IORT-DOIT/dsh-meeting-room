# v8 方案：让会议室自己往下走（取消“回合制”静默）

## §0 用户原文（唯一范围依据）

User said (m06172)：

> 为什么会出现这种回合制会话的情况？请做出修改

（附图证据：会议室「你们为什么暂停?」里 实验2 / 实验1 各自解释「我们这类会话是回合制：没有新消息就不产生动作，看起来像暂停，其实是在待命」；实验2 还指出「前面对插件提的那条：默认 archive 只写记录、不推送，两个与会者都不会被从空闲里叫起来」。）

## §1 根因（一手取证，基于 v7 冻结快照）

1. **与会者是被动唤醒的会话**：它们只能被「投递给它的一条消息」触发 —— `index.js:1381-1431` `relayWithEffort()` → `relay()`（`:1360-1368`）/ `relayFromAgentWithId()`（`:1399-1407`）→ `agent.followup(message)`。没有投递就没有动作。这不是 bug，是宿主机制；「自动往下走」必须由插件主动投递来实现。
2. **触发投递的入口只有两个**：
   - 人类发言 `POST /rooms/:id/post`（`index.js:2118-2153`），且仅当 `mode !== 'archive'` 才 `deliver()`（`:2141`）；
   - 与会者工具 `room_say` 显式传 `to` 或 `mode: 'notice' | 'full'`（`index.js:2727-2739`）。
3. **缺省是 archive**：`room_say` 的默认在 `:2696`（描述「默认只写进会议记录（不打扰别人）」）与 `:2727`（只有 notice/full 才投递）⇒ **与会者发言不唤醒任何人** ⇒ 用户说一段 → 每人各答一次 → 房间静止。这就是用户看到的「回合制」。
   - 真机还叠了第二因：现在跑的是 v6.1，那时客户端发帖根本不带 `mode` ⇒ 缺省 archive，连**用户自己的发言**都不推送。v7 已改成恒带 `mode:'notice'`（`client.js:1207-1208`），但**尚未重启 DSH ⇒ 未生效**。
4. **附带缺陷（自环风险）**：`deliver()` 的缺省 `targets` 取全体成员（`index.js:651`），不排除 `senderSessionId` 本人 ⇒ 与会者用 `mode:'notice'` 不点名时会把通知投给自己，理论上自我循环。

## §2 设计（最小改动；**不新增任何 UI 控件、不新增工具**）

### 2.1 宿主 `index.js`

1. **排除发言者本人**：`deliver()` 解析成员后过滤掉 `member.sessionId === senderSessionId`（`:651` 之后一行）。纯安全修正。
2. **房间级自动接力（核心）**：
   - Config 新增 `autoContinueHops: z.number().default(6)`：一次人类发言之后允许自动接力几跳；`0` = 关闭。**只在插件配置与文档里出现，不加进任何面板**。
   - 房间内存态 `room.autoHop` / `room.autoCapNoticed`（**不写 room.json**，避免动持久化白名单；重启归零无副作用）。
   - `room_say` 的**缺省路径**（既没传 `to`，也没显式传 mode）= 「写进记录 + 自动接力」：`room.status !== 'closed'`、除自己外还有成员、`autoHop < cap` ⇒ `autoHop++`，并向**除发言者以外的全体成员**投递 `notice`；否则只归档。
   - **显式 `mode:'archive'` 仍然是「只记录、不打扰」**（给与会者留一个沉默档，也保住既有语义）。
   - 自动接力专用文案（**不含任何人的发言正文**）：
     `【会议室 X】<发言者> 有新发言（#N）。用 room_read 看完整记录；有新意见或要回应就 room_say，没有新内容就不必发言。`
     （人类发言走原文案，不变。）
   - **该文案必须原样送达，不能再被 `deliver()` 包一层**（否则房名重复两次，正是 v6/v7 的 P3-a 现象）：给 `deliver()` 增可选参数 `noticeStyle`，当 `noticeStyle === 'ping'` 且 `mode === 'notice'` 时 `finalText` **直接取**上面这句（不拼接 `authorLabel`/`body`），且**只用 `latestSeq`/`authorLabel`，绝不引用 `text`**。（2026-09-29 Lead 追加，源自 verifier 的提前提示。）
   - **触顶**时 `appendSystem('自动接力已达上限（6 跳），等待你的指令。')`，每个用户消息周期最多一条（`autoCapNoticed` 去重）。
   - 人类 `POST /post`（`:2137` 之后）把 `autoHop = 0`、`autoCapNoticed = false` ⇒ **你每发一次言就重新拿到额度**。
3. 工具描述同步（给 AI 看的契约）：`room_say` 的 description 说明「缺省＝记录 + 自动接力提醒其他与会者；只要记录不打扰就显式传 `mode:'archive'`；要点名就传 `to`」（`:2695-2696`）。

### 2.2 客户端 `client.js`（只改文案，不加控件）

- 「策划会议」抽屉说明（v7 现 `:1585`）与 composer 提示行（v7 现 `:1326`）各加一句：`与会者之间的发言会自动接力（默认最多 6 跳）；没人有新意见就自然停下。`
- 触顶系统行已能被现有渲染吃下（`client.js:1338-1344` `kind === 'system'`），无需新样式。

### 2.3 自测 `selftest/run.mjs`

- 改既有断言：`:2864-2865`（agent 缺省 `room_say` 现在会接力 ⇒ 「归档 + 向其他成员投递」）。
- 新增：排除本人；显式 `mode:'archive'` 不接力；上限截断 + 系统行**恰一条**；`autoContinueHops = 0` 关闭；`room.status === 'closed'` 不接力；人类发言把 `autoHop` 归零；接力 notice 文本**不含**任何发言正文（哨兵串）；工具数与既有断言只增不减。
