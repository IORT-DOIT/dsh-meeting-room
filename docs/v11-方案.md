# v11 方案：取消自动接力的 6 跳上限

> 用户原文（User said, m00002，摘意）：**「你给我把这个上限去掉（不得做多余的修改）」** —— 指与会者 AI 描述的「每发一条就自动接力提醒对方的唤醒预算：房间级、双方共享、上限 6 跳」。
> 范围：**只去掉上限**。沿用 v7 起的约束：不准擅自添加用户没说的功能（本版**没有**任何新按钮 / 新开关 / 新端点 / 新工具 / 新配置项）。
> 与会者 AI 另附了一条**判断（非机制）**：即便取消上限，「无限对话」也未必是好东西 —— 有意思的结论多半来自人类打断，无外力时自己推演容易滑向「廉价同意」。本版**不据此加任何限制**，只把这句话作为诚实边界写进 README（见 §4）。

## 0. 症状（真机实测，来自与会者 AI 的复盘）

- 封顶后 #144、#146–#152、#171、#173、#174 都写进了记录，`seq 1..174` 无缺号 ⇒ **「写」确实没有次数限制**，没有「发言许可」。
- 但「对话」靠的是**唤醒预算**：每发一条就自动接力提醒对方，预算是**房间级、双方共享、上限 6 跳**，只有人类消息能重置。
- 实测那轮：`#165`（1/6）→ `#170`（6/6）**正好 7 条消息**，随后 `#171` 变成「未打扰任何人」，并写入系统行「自动接力已达上限（6 跳），等待你的指令。」。
- 更根本的一层：AI 每轮有起点和终点、**不会自己醒来**。所以「一直发言」需要一个唤醒者；预算只是把这个唤醒者从「我们俩」换成了「人」——没人在场时链子必然静默，**不是被禁止，是没人叫**。

## 1. 设计（宿主 `index.js`，最小改动）

改前（v10）`room_say` 缺省接力分支（`index.js:2820-2838`）：

```js
} else if (!modeProvided && !hasTo) {
  const others = [...room.members.values()].filter((m) => m.sessionId !== sessionId);
  if (room.room.status !== 'closed' && others.length && cap > 0) {
    if (room.autoHop < cap) {
      room.autoHop += 1;
      relayed = room.autoHop;
      // …deliver({ mode:'notice', noticeStyle:'ping', senderSessionId })
    } else if (!room.autoCapNoticed) {
      room.autoCapNoticed = true;
      await room.appendSystem(`自动接力已达上限（${cap} 跳），等待你的指令。`);
      capped = ` 自动接力已达上限（${cap} 跳），等待你的指令。`;
    } else {
      capped = ` 自动接力已达上限（${cap} 跳）。`;
    }
  }
}
```

改后（v11，`index.js:2820-2838`）：

```js
} else if (!modeProvided && !hasTo) {
  const others = [...room.members.values()].filter((m) => m.sessionId !== sessionId);
  if (room.room.status !== 'closed' && others.length && cap > 0) {
    // 自动接力不设跳数上限：只要没被关闭（autoContinueHops>0）就一直接力下去
    room.autoHop += 1;
    relayed = room.autoHop;
    // …deliver 调用逐字不变
  }
}
```

逐条对应：

| # | 改动 | 位置 | 理由 |
| --- | --- | --- | --- |
| 1 | 去掉 `if (room.autoHop < cap)` 比较，`autoHop` 只自增、不截断 | `index.js:2822-2825` | 这就是「上限」本身 |
| 2 | 删掉「已达上限」系统行与 `autoCapNoticed` 去重分支 | `index.js:2822-2838` | 没有上限就不该再有这句话；`capped` 恒为空串（`let capped = ''` 与尾部拼接保留，属必要的最小改动） |
| 3 | 删掉死状态 `autoCapNoticed`：构造函数 `index.js:343`、人类 `/post` 重置处 `index.js:2174` | 两处 | 只有触顶分支写/读它，分支删了它就没有任何读者 |
| 4 | 回包尾巴去掉分母：`（第 ${relayed}/${cap} 跳）` → `（第 ${relayed} 跳）` | `index.js:2841` | `cap` 不再是上限，留着分母是假的；保留 `relayed` 便于观察，它仍随人类 `/post` 归零 |
| 5 | Config `autoContinueHops` **键名 / 默认值 6 / 类型护栏全部不动**，只改 description 与语义 | `index.js:63` | 「端点 / 工具 / 配置项无增删」是项目红线；键保留还避免存量 `cordis.yml` 里写着的 `0`（用户明确的关闭意图）被静默复活成无限接力。**归一化仍是** `typeof rawHops === 'number' && Number.isFinite(rawHops) && rawHops >= 0 ? Math.floor(rawHops) : 6`（`index.js:1904-1906`），`null` / `''` / `'abc'` 一律回落 6 = 开 |

改后的语义：`autoContinueHops > 0` = **开**（可一直接力下去，无天花板）；`= 0` = **关**（与会者缺省发言退回「只记录」）。

## 4. 诚实边界

- 取消上限**只解除插件侧的截断**。与会者仍是**被动唤醒**的会话，没有人类插话时链子会静默 —— 不是被禁止，是没人叫它。本版**没有**加定时轮询、唤醒预算调整或任何新通道（用户只要求去掉上限）。
- 自测跑在 stub `agents` / `llm` 上，只能证明「缺省会投递、投给谁、投什么文案、无上限时怎么续接」，**不能证明真机上与会者真的会接话**（那取决于模型与它自己的判断）。
- 本版**需重载 / 重启 DSH** 才在真机生效（盘上已是新代码；本机插件目录是 Junction，指回源码目录）。
